## 2025-02-13 - Layout Thrashing in Input Handlers
**Learning:** Performing a DOM write (`el.style.height = 'auto'`) followed immediately by a DOM read (`el.scrollHeight`) inside an `oninput` handler causes forced synchronous layouts (layout thrashing) on every keystroke. Wrapping this in `requestAnimationFrame` defers the heavy work out of the event loop task and unblocks the main thread (improving typing responsiveness), although it still forces synchronous layout during the render phase. Multiple events in a single frame can queue redundant calculations.
**Action:** Always wrap DOM reads/writes in high-frequency event handlers (like scroll, resize, input) within a debounced `requestAnimationFrame` callback. Use `cancelAnimationFrame` to ensure only the latest layout recalculation is executed per frame.
